# 框架选型决策：Agent 核心不引入现成框架

- **状态**：已定稿（2026-07-27）
- **决策**：`deepseek-code-agent` 的 Agent 核心（agent loop / 工具调度 / 权限闸门 / 上下文治理 / 早退机制）**不引入任何现成 Agent 框架**，维持零依赖手写 Harness。
- **反向决策同样成立**：若将来必须引入，也**不**选 LangChain / AutoGen / CrewAI 这类"重抽象 / 多智能体"框架。

---

## 背景

项目定位：中文原生、DeepSeek 官方直连的编程 Agent，作为**可观测、可恢复、可控制**的教学级 + 产品级 Harness 实现。简历与面试叙事的核心卖点是「从 0 自建内核，不依赖任何 Agent 框架或中转」。

本决策只覆盖 **Agent 核心编排层**；不限制对「库」的使用（见后果与边界）。

---

## 候选框架对比

| 框架 | 类型 | 适配度 | 关键否决理由 |
|------|------|:------:|--------------|
| **LangChain / LangGraph** | 通用 LLM / 图状态框架 | ❌ | 抽象过厚，loop 与上下文被封装；依赖树大、版本漂移快；采用即与「自研内核」卖点直接冲突 |
| **LlamaIndex** | RAG / 数据索引框架 | ❌ | 管检索索引、不管 agent loop；本项目轻量 RAG 已自研，错层 |
| **AutoGen / CrewAI / Agno** | 多智能体对话框架 | ❌ | 多 agent 是其默认范式；本项目 2026-07-26 已把「双核多 agent」架构整体回退——正是它们引入了路由不可靠 + 主循环死循环 + 补丁叠补丁 |
| **Vercel AI SDK (`ai`)** | provider 无关 TS 工具包 | ⚠️ | 类型干净，但仍把 loop 抽象成它自己的原语，要把项目改成它的模型；且夹带 UI 关注点 |
| **pi-agent-core** | 极简终端 coding harness | ⚠️ | 哲学最贴近（极简、TS、可扩展），但采用会让本项目变成「pi 的封装层」，直接消解「0→1 自研内核」这一最大差异化 |

**结论**：上述框架要么抽象过厚、要么范式冲突、要么消解项目差异化。**没有一个值得引入。**

---

## 为什么是「零框架手写」（核心理由）

1. **学习目标就是 Harness 本身**
   框架把循环 / 工具 / 上下文封装起来，学不到「Agentic 能力来自模型、工程价值在 Harness」这一层。手写才能精确控制权限闸门、压缩时机、early-exit 等治理点——这正是生产级 Agent 与 Demo 的分界。

2. **双核实验是反向实证（最关键的一条）**
   我们曾自建一套更复杂的「框架化」架构——`Flash 主循环 + Pro 规划/反思 + 元认知路由 + 契约 + 认知黑板`。实测暴露：
   - 路由不可靠：Flash 自评复杂度，短句（如「审 main.py」）误判简单走单步，完全不调工具；
   - 主循环死循环：`while(!done)` 对 tool_call 不设 done，Flash 反复 `read_file` 20+ 次；
   - 补丁叠补丁：`Gate1` 正则补丁、分析误判补丁…… 每个环节都要打补丁防「看不见 / 不收敛 / 误判」；
   - **测试通过 ≠ 修复有效**：6 次 fix commit 多靠打补丁，原始症状（反复 read）未真正消失。
   
   最终 `git reset --hard d4b00c8` 回退，备份 tag `backup-pre-dualcore-20260726`。**这证明：哪怕是自己写的框架化抽象，叠在简单 loop 上也会爆炸。** 外部框架只是把这种不透明和补丁成本外包出去，还附赠依赖与版本漂移。

3. **依赖精简是特性，不是偷懒**
   评估报告确认运行时仅 `openai / zod / ink / react / chalk / @huggingface/transformers`，无重型框架；零框架让我们对行为、升级、可移植完全可控。

4. **差异化即资产**
   对校招 / 实习简历，「亲手实现 Harness」比「调一个 SDK」更能体现系统设计与工程判断，是核心卖点。引入框架会直接削弱它。

---

## 后果与边界

- **代价**：工具 / 记忆 / 技能等能力需自行实现与维护——但这恰是项目价值来源，而非负担。
- **边界（库 ≠ 框架）**：不排斥「库」——`openai`（API 兼容）、`zod`（schema 校验）、`@huggingface/transformers`（本地 embedding）都是库而非框架，继续使用。
- **扩展点保留**：MCP 接外部工具、技能系统沉淀工作流，均可在**不改主循环**前提下接入。
- **触发重审条件**：若 DeepSeek 生态出现官方 / 事实标准的轻量 Harness 框架，或项目规模扩张到自研成本显著高于收益，再重审本决策。
